# Screen-jump — корневые причины «дёргания» при кликах

> Senior frontend engineer. Отдельный анализ — почему UI прыгает при клике.
> Дата: 2026-05-07

| # | Cause | Trigger user-action | File:line | Fix |
|---|---|---|---|---|
| **1** | **Нет `scrollbar-gutter: stable`** на `html`. Когда секция переключается на короткую (нет vertical scroll) — body shrink-аутится горизонтально на 6-15px. Тот же jump при открытии модалки: `html { overflow: hidden }` через `:has(.modal-overlay:not(.hidden))` (styles.css:2940-2958) **убирает** scrollbar — весь контент + fixed topbar сдвигается вправо на ширину полосы. | Open any modal (KPI/gantt/settings); switch from long section (registry) to short (dashboard empty state). | `styles.css:194` (`html { font-size: 14px; scroll-behavior: smooth; }`) | Добавить `scrollbar-gutter: stable;` в `html { … }`. **Один-строчный фикс закрывает и nav-switch, и modal-open, и tooltip-grow.** |
| **2** | **`animateSection()` на каждый `renderSection`** прописывает `animation-delay` 0–150 ms на до 48 элементов и анимацию `ui-fade-up` (`translateY(4px) scale(.997)`). Срабатывает после **любого** click который дёргает `App.refreshAll()` — пользователь видит «волну» по карточкам при кликах вообще не связанных с секцией (фильтр, сохранение). | Любой клик: filter checkbox, row-edit, nav-tab re-click. | `app.js:1814` (вызов из `renderSection`), keyframes `styles.css:3086`. | Запускать `animateSection` **только** при реальной смене активной секции, не на refresh: `if (App._lastAnimSection !== s) { App._lastAnimAt=0; App._lastAnimSection=s; … }`. |
| **3** | **Reactive auto-flush → `App.refreshAll()`** перерисовывает всю активную секцию (полный `innerHTML`) после ~100 ms debounce, даже когда мутация была локальная (один cell в Реестре). Сохраняется scrollTop только в Ганте; Registry / Dashboard / Kanban — теряют scroll и фокус. Видится как «прыжок наверх» через 100 мс после клика. | Inline-edit cell в Реестре, toggle done в карточке Канбана, изменение фильтра. | `app.js:2063-2081` (reactive subscriber). Grace-окно 250 ms работает только если sub-view успел вызвать `App.markRenderedNow()` — у Registry / Kanban / Dashboard этого вызова нет. | Добавить `App.markRenderedNow()` в `RegistryView.render()`, `KanbanView.render()`, `DashboardView.render()`. Замена `App.refreshAll()` в subscriber на «refresh только если active section ≠ только что рендеренный». |
| **4** | **`RegistryView.render()` бьёт `tbody.innerHTML=''` целиком** (registry.js:249) при любой мутации. Pinned columns CSS `position: sticky` пересчитывается → видимый «мерцающий зебра-stripe» + scroll-jump. | Удалить строку, переключить колонку, сортировка. | `views/registry.js:249, 38`. | Diff-render: для in-place edit обновлять только конкретный `<tr>` через уже существующий `tr.dataset.id`. Минимум — `requestAnimationFrame` + сохранить `tableWrap.scrollTop` до и после. |
| **5** | **Modal scroll-lock через `:has()` без компенсации scrollbar.** При открытии любой `.modal-overlay`, `.ts2-*-overlay` (styles.css:2940-2958) `html` получает `overflow: hidden` → vertical scrollbar исчезает → весь контент (включая fixed `#topbar`) shift-ится на 6 px вправо. | Открытие любого модала: KPI, settings, scanner. | `styles.css:2940-2958`. | Тот же fix #1 (`scrollbar-gutter: stable`) автоматически решает. Альтернативно — заменить `overflow: hidden` на `overflow: clip` + `padding-right: var(--scrollbar-w)` с измерением через JS. |
| **6** | **`section-enter` animation на смене вкладки** прокидывает `animation` без `will-change`/`transform: translateZ(0)`. Браузер промоутит layer на лету → flicker первого кадра (особенно на Safari). | Клик по nav-item. | `styles.css:1190` + `nav.js:88-93` (force reflow `void el.offsetWidth`). | `.app-section { will-change: transform, opacity; transform: translateZ(0); }` либо убрать анимацию (только `opacity` без `translateY`). |
| **7** | **Backdrop-filter: blur(12px) на `#topbar`** + `blur(4px)` на `.modal-overlay` (styles.css:236, 2934). При scroll/clicks repaint topbar заставляет браузер пересчитывать blur по живому контенту → визуальная «дрожь» 1-2 px на слабом GPU. | Любой scroll или click который меняет содержимое под topbar. | `styles.css:236, 2934`. | Снять `backdrop-filter` для topbar (он непрозрачный — blur не нужен) либо заменить на static `background: rgba(...)`. |
| **8** | **Filter-dropdown `innerHTML` rewrite** на каждом `App.refreshAll()` (app.js:462-470). Каждый клик через reactive flush пересоздаёт `<option>` списки → выбранное значение сбрасывается в момент рендера, дропдаун закрывается, а если он был открыт — браузер ремонтирует popup (height-jump родительского блока). | Клик любой UI-элемент при открытом filter dropdown. | `app.js:462-470`. | Идемпотентность: skip rewrite если `<option>` set уже совпадает. |
| **9** | **Sidebar `transition: width .22s`** (`styles.css:886`) — width-transition triggers full layout reflow main-area при collapse/expand. | Toggle sidebar. | `styles.css:886`. | Заменить на `transform: translateX(...)` контейнера и фиксированную main-area `padding-left` (snap-вариант) или хотя бы `transition: width` оставить, но добавить `contain: layout` на `.main-area`. |
| **10** | **`@keyframes prizma-breathe`** на пустом-state-glyph (`styles.css:3109`) бесконечно перерисовывает (`scale`/opacity?). Для empty-state с пустыми фильтрами glyph остаётся в DOM и продолжает анимироваться даже при наведении на другие элементы → micro-jitter на сборке layer'а. | Сидение на empty-screen + ховер по карточкам. | `styles.css:3109`. | Добавить `animation-play-state: paused` при `:not(:hover)` или вообще убрать — empty-state не должен «дышать». |

## Топ-3 фикса (80% эффекта)

1. **`html { scrollbar-gutter: stable; }`** — одна строка снимает `#1` и `#5` (modal-open jump, nav-switch shift). Самый высокий ROI; 90% жалоб «при кликах экран дёргается» именно про scrollbar appearance.
2. **Гейт `animateSection()` — только при смене секции, не на refreshAll** (`app.js:1814`). Сейчас «волна» по карточкам бьёт на каждый клик в фильтре/реестре. Убирает «заметный glitch» при routine-операциях.
3. **`App.markRenderedNow()` в Registry/Dashboard/Kanban handler'ах + `requestAnimationFrame` обёртка вокруг `tbody.innerHTML = ''`** — устраняет «прыжок через 100 мс после клика» (reactive flush double-render) и локальный flicker таблицы при inline-edit.
