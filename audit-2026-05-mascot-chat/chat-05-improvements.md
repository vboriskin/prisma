## 2. Multi-turn

Сейчас: каждый message — изолированный prompt; история хранится в `chatHistory` массиве, обрезается окном 8 сообщений (см. `chatPrompts.js`).

Улучшения:
- **Sliding summary**: после 6 turns конденсировать в `conversationMemo` (1-2 предложения) и держать в system-prompt отдельной строкой.
- **«Напомни контекст»** — slash `/контекст` возвращает текущий memo: «обсуждаем перенос PRZM-44, Иванов отказался брать Q2».
- **Pinned facts** — пользователь жмёт скрепку на сообщении, оно липнет к prompt до конца сессии.
- **Cross-session memory** — last 3 темы дня сохранять в localStorage, на новом старте маскот: «вчера разбирали риск по эпику Acquiring, продолжим?».

## 3. Proactive suggestions

Триггеры:
- **Route-enter**: при заходе на дашборд, если ≥3 задачи at-risk → маскот всплывает с «Покажу 3 задачи в зоне риска?» (только chip, без модала).
- **Anomaly hook**: на каждом тике scanner (BB/CF) если delta > 1.5σ → notification badge на иконке чата.
- **Time-based**: пятница 16:00 → «Подготовить статус для CEO?».
- **Idle**: 90 сек на одной задаче без действий → «Нужна помощь с этой задачей?».

Throttle: не более 1 проактивного сообщения в 20 мин, dismiss → cooldown 24ч.

## 4. Tool-use, 3 конкретных tool'а

**`searchIssue(query, filters)`** — fuzzy-поиск по реестру + Jira fallback. Возвращает top-5 issue с linkами. LLM решает, нужно ли уточнять у пользователя. Триггер: «найди задачу про авторизацию в карты».

**`computeCoverage(epicId)`** — считает % покрытия Zephyr-тестами для эпика, вытягивает gaps. Триггер: «как с тестами по эпику Acquiring?». Возвращает JSON `{covered: 0.78, gaps: [...]}`, LLM формулирует ответ.

**`postConfluenceComment(pageId, body)`** — пишет коммент с пометкой «черновик от Призмы» (требует confirm-chip от пользователя — explicit permission). Триггер: «оставь коммент на странице ретро Q1».

Архитектурно: tool-схема в `chat/tools.js`, dispatcher в `llmAssistant.js`, GigaChat function-calling. Маскот переходит в state `ls-tool` пока вызов идёт (уже есть).

## 5. Брендовая личность

Да, голос нужен — иначе маскот и чат рассинхронизированы. По §13.1 — «спокойный наблюдатель команды»: краткий, без восклицаний, без эмодзи (кроме маскота-аватара), факт + опция действия.

Запрет: «сорри», «к сожалению», «я всего лишь AI».

Шаблон: «<факт>. Хочешь <действие>?». Имя — оставить «Призма», без человеческого имени, чтобы не сваливаться в parasocial.

## 6. Onboarding chat-tour (5 шагов)

1. Маскот появляется в нижнем-правом, ls-move к Реестру: «Здесь живут все 5k задач квартала».
2. ls-move к Ганту: «Перетаскивай — я подскажу конфликты по людям».
3. ls-move к Дашборду: «Курс квартала: burn-down, риски, скорость».
4. ls-move к Сканнеру: «Слушаю Jira/BB/CF — предупрежу об аномалиях».
5. Возврат в чат: «Спроси: 'план на неделю' — покажу старт».

Skip-кнопка после шага 1, прогресс сохраняется в localStorage.

## 7. Voice/dictation

Да, для тимлидов в коридорах между 1:1 — высокий impact. MVP: Web Speech API, кнопка-микрофон в assistant-panel `index.html`. Гипотеза: 25% мобильных сессий перейдут на голос. Ограничение: только dictation → text, без voice-output (open-space).

## 8. Slash-commands

Полезно как ускоритель для power-users (delivery-менеджеры). Набор: `/перенеси`, `/анализ`, `/проверь`, `/риски`, `/нагрузка`, `/ретро`. Реализация: автокомплит в input, при выборе подставляется шаблон с плейсхолдерами. Метрика: доля сообщений со slash → если >15% за месяц, расширяем словарь. Discoverability: первый «/» показывает popover с 6 командами и примерами.
