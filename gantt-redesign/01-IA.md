### 1.4. Четыре контракта Ганта — нельзя ломать

1. **DnD-валидаторы (`cell.drop` + `_kbDrop`).** Любой mouse-drop и keyboard-drop проходит цепочку: `cross-epic guard` → `same-col guard` → `activeSection guard` → `row-still-exists guard` → `requireMoveComment` (если plan-locked && !editMode) → `moveWtBetweenCols` → re-render + Align. Игорь: «50–80 drag в день» — это рабочая поверхность. Любая регрессия здесь = регрессия рейтинга 4/5.
   _Якоря:_ `gantt.js:1536-1623` (mouse), `gantt.js:1717-1801` (keyboard).
2. **Plan-lock + editMode (V14 B5 / V17 P2 CRIT-3).** Когда `state.planLocked === true` и edit-mode выключен — **каждый** перенос требует комментарий. Edit-mode bypass'ит модалку, но всё равно записывает audit-entry `[edit-mode]` в `transferComments[]`. Без этого — дыра в compliance use-case.
   _Якорь:_ `gantt.js:725-735, 1574-1596`.
3. **Cross-epic guard.** Pill приклеена к строке (data-row-id). Drop в чужой эпик отклоняется toast'ом «Перенос между эпиками не предусмотрен» + reject-pulse. Тот же guard — в kb-DnD (UI-инвариант, не валидируется повторно).
   _Якорь:_ `gantt.js:1559-1562, 1727-1734`.
4. **Mass-mutations через Reactive.silent.** Любая массовая правка состояния (CSV import, snapshot restore) обязана быть в `Reactive.silent(() => …)` — иначе infinite loop. Гант это потребляет через `Storage.save()` после `moveWtBetweenCols`. Не наш контракт, но при любой переделке state-mutation в Ганте — соблюдать.
   _Якорь:_ `CLAUDE.md § 3 контракта`.

## 2. IA-проблемы (5 пунктов)

### 2.1. Шапка Ганта — стек из четырёх «головных» элементов

Сейчас сверху подряд: prizma-page-header (eyebrow + h1 «Гант» + sub) → legacy `.section-header h2 «Гант по релизам»` → toolbar из 12 кнопок → подсказки-блок (если развёрнут) → `#gantt-filters` (пустой) → board.

Это **то же самое что было на дашборде до П4-MS Wave 5** — h2 дублирует prizma-h1. На дашборде h2 уже сняли (legacy `<h2>Метрики</h2>` убран как тавтология с eyebrow «КУРС · МЕТРИКИ»). На Ганте — остался.

### 2.2. Toolbar-крематорий: 12 кнопок без группировки

`gantt-lock-status / Зафиксировать / Подсказки / История / Edit / Unlock / 🔍 / Layout / Density / Collapse / Undo / Redo / Fullscreen` — длинная горизонтальная лента, в которой смешано:
- **режим работы с планом** (lock, edit-mode, unlock) — критическая branch'ующая логика
- **управление видом** (mode, density, expand-all, fullscreen) — безопасные настройки
- **навигация** (jump-palette, history) — overview-инструменты
- **system** (undo/redo) — глобальное

Дмитрий П12: «Топбар — 10 кнопок-иконок без группировки. Между Save и Sim mode мне нужен зазор глазами». Тот же диагноз воспроизводится один-к-одному на Ганте. Дмитрий — 4/5, Игорь — 4/5; группировка стоит «S» эффорта при «средне-высоком» эффекте — quick win.

### 2.3. Первый экран не содержит «что требует курса»

На дашборде мы установили паттерн: hero → action-блок «что требует курса сегодня» → progress → KPI. Гант сейчас открывает доску, но **никак не показывает где боль**: какая команда перегружена, у какого эпика 5+ переносов, какой релиз отстаёт от плана. Информация **есть** в DOM (sparkline overload, flow-badges +N/−N, count-chips), но они растащены по 5 разным местам в gantt-header / team-row.

Власть над фокусом не отдана пользователю явно. Игорь делает 50–80 drag в день — он не имеет точки старта «вот сюда сегодня смотри».

### 2.4. Полка `#gantt-filters` — мёртвый код

```js
renderFilters() {
  const el = document.getElementById('gantt-filters');
  if (el) { el.innerHTML = ''; el.style.display = 'none'; }
}
```

Контейнер живёт в DOM, объявлен в blocks-toggle (`appSettings.js:139 → 'Фильтры ганта'`), но render всегда чистит и прячет. При этом `GanttView.gf` (team / scope / onlyBlocking / onlyNoRelease / onlyRisky) **читается** в `getRows()` — мёртвый UI, живой code-path. Фильтры доступны только глобально через FilterEngine (топбар), что путает: Дмитрий ожидает per-view фильтров, Игорь — нет.

### 2.5. Дублирование с Реестром / Канбаном / Таймлайном

Все 4 view'а модуля СЛЕД ПУТИ работают **с одним и тем же набором данных** (`state.rows`), показывают **одни и те же релизы** (1.20/1.21/1.22/OT/Бэклог), используют **один FilterEngine.getFiltered()**. Различаются только проекцией:

| Действие                  | Реестр   | Гант     | Канбан   | Таймлайн |
|---------------------------|----------|----------|----------|----------|
| Просмотр всех задач       | ✓ (rows) | ✓ (pills)| ✓ (cards)| ✓ (bars) |
| Назначить релиз           | inline   | DnD pill | DnD card | —        |
| Сменить состояние         | inline   | ctx-menu | DnD col  | —        |
| Bulk-действия             | ✓        | —        | —        | —        |
| Inline-edit поля          | ✓        | —        | —        | —        |
| Time-axis (даты на оси X) | —        | implicit (по релизам) | — | ✓        |
| История переносов         | —        | trail-rows | —      | —        |

→ Подложку и Историю П12 уже отметил как кандидаты на схлопывание. Реестр / Гант / Канбан / Таймлайн остаются как 4 independent screens, требующих **повторной настройки фильтров** при каждом переключении.

## 3. Cross-comparison: Гант vs Реестр vs Канбан vs Таймлайн

### 3.1. Что общего

- **Источник:** `FilterEngine.getFiltered()` → `state.rows`
- **Сущность строки:** Эпик (row) с per-release массивами types (release120Types …)
- **Категории:** релизы 1.20/1.21/1.22/OT/Бэклог — пять колонок, _одинаковые во всех 4-х view'ах_
- **prizma-page-header** через `_injectPrizmaHeader('gantt'/'registry'/'kanban'/'timeline')` — already unified
- **Sub-line «20.04–17.05»** для дат релизов — _технически дублируется_ строкой в `gantt.js:618-621` и `timeline.js:38-41`
- **Empty-state:** prizmaEmptyGlyph + «Нет данных» — already unified

### 3.2. Что уникально

- **Гант:** DnD work-type pill между релизами; per-pill state (todo/in-progress/done/unplanned); trail-rows истории; plan-lock с обязательным комментарием; keyboard-DnD; per-team rail-hue; sparkline-overload; flow-badges +N/−N; today-pill.
- **Канбан:** DnD карточки между релизами целиком (а не per-pill); один drop = смена релиза для всей строки; нет history; нет per-pill states.
- **Таймлайн:** Time-axis с реальной шкалой дат (не categorical); summary / detailed mode; per-team distribution; **no DnD**.
- **Реестр:** Inline-edit любого поля, bulk-actions (50–200 строк за операцию), сортировка/группировка, Cmd+K-фрагмент через `btn-toggle-cols`, авторитет — здесь именно «вводят» данные.

### 3.3. Реалистичен ли merge сейчас

**Нет.** Дмитрий П12 предложил «один таб с layout-toggle» (Реестр/Гант/Канбан/Таймлайн) — это вариант **γ** ниже. По нашему анализу:

1. **Контракты пилюли в Ганте + DnD-валидаторы + plan-lock + keyboard-DnD** — это ~700 LOC в `gantt.js` сложной логики. В Реестре inline-edit — другой ~500 LOC контракт. Объединить layout-toggle, не нарушив ни один контракт, требует промежуточного слоя «view-controller», которого нет.
2. **Тесты:** 534 unit'а распределены по renderHelpers / гант / реестр. Layout-toggle ломает test boundary.
3. **Анна (3/5 рейтинг Гант = 1/5)** — её путь «дашборд → клик KPI → Реестр с фильтром» уже работает. Объединение не помогает её use-case.
4. **Игорь / Дмитрий (4/5 на Ганте, 5/5 на Реестре)** — у них разный flow. Игорь не хочет «один таб» — он хочет **меньше переключений** между ними, а это другая задача (см. β).

→ **Минимальный шаг к unified-pattern:** общий filter-bar выше всех 4-х view'ов, разделяемый между ними при переключении (persisted в `state.activeFilters`). Это вариант **β**, и он реалистичен в спринте редизайна Ганта.

## 4. Решение по архитектурным вариантам

### Вариант α — только Гант refresh (как было с Дашбордом)

**Что:** редизайн в границах `section-gantt`. Toolbar-группировка, action-блок «что требует курса», dead `#gantt-filters` убираем, h2-тавтологию снимаем (как `metrics.js`), motion усиливаем.

**Pros:**
- Изолированный риск, контракты Ганта не выходят за пределы файла
- Точно реплицирует паттерн дашборда — синхронизация дизайна между разделами одного бренда
- 1–2 спринта (как дашборд), 1017 тестов остаются зелёными
- Дмитрий и Игорь получают свой 4→5

**Cons:**
- Дмитрий П12 #6 («один таб») остаётся неуслышанным
- Анна и Светлана (1/5) не получают улучшений — для них Гант остаётся «не открываю»
- Filter-state по-прежнему сбрасывается при переключении на Реестр

### Вариант β — унифицировать toolbar/filter-bar с Реестром, view'ы остаются разные

**Что:** Над всеми view'ами модуля СЛЕД ПУТИ (Реестр/Гант/Канбан/Таймлайн) — единый horizontal **filter-bar** + view-switcher tabs (текущие модуль-табы) + общий `prizma-page-header`. Toolbar-кнопки специфичные для Ганта (lock/density/mode/jump/expand/fullscreen/undo) уезжают в **secondary toolbar** под filter-bar **только** на Гантовом view'е. Единые quick-actions «команда» / «релиз» / «scope» — общие.

**Pros:**
- Реализует «filter-state не сбрасывается при переключении» — ключевая боль из П12 Игоря
- Подаёт визуальный сигнал «это семейство view'ов одного домена», как мы уже сделали с модулями-иконками в брендбуке §5
- Дмитрий П12 #6 частично закрыт — переключение между Реестром и Гантом становится дешёвым
- Не ломает контракты Ганта; гантовая toolbar уезжает в secondary, но остаётся
- Контракты Реестра тоже не ломаются

**Cons:**
- Эффорт L (1.5–2 недели) — затрагивает 4 view'а одновременно
- Нужен новый общий компонент `path-shared-toolbar.js` — это новый код-сурс (не было)
- Persistance filter-state требует мини-изменения `state.activeFilters` (схема state)
- Risk на регрессии в Реестре, на котором сейчас Дмитрий и Игорь ставят 5/5

### Вариант γ — полный merge: один таб «Задачи» с layout-toggle

**Что:** Свернуть 4 view'а в один экран `section-tasks` с переключателем сегментным «Таблица / Гант / Канбан / Таймлайн». Разные projection-стратегии под одним shell'ом.

**Pros:**
- Прямо отвечает Дмитрию П12 #6
- Сильнее всего сокращает sidebar (4→1)
- Filter-state живёт в одном месте по умолчанию

**Cons:**
- **Очень большой эффорт** (4–6 недель, аналогично «volume of dashboard redesign × 2»)
- 4 разных контракта (DnD-pills, DnD-cards, inline-edit, time-axis) под одним shell'ом — большой риск регрессий, особенно для plan-lock и keyboard-DnD
- Игорю (5/5 на Реестре) и Дмитрию (4/5 на Ганте) добавляет когнитивную нагрузку первые недели — они привыкли к **отдельным** screen'ам как к мускульной памяти
- Анне это не нужно — она в Гант не ходит ни в каком виде
- 534 unit'а потребуют масштабной перестройки test boundary
- Ребрендинг в «Призму» сейчас в активной фазе — этот пакет добавляет одновременно и архитектурный refactor, и визуальный — слишком большой риск

### Финальная рекомендация

> **β** для текущего раунда + закладываем путь к γ позже.
>
> **β** даёт большую часть ценности γ (unified filter-state, общий header, ощущение «семьи view'ов») при значительно меньшем риске и без касания contractов DnD/inline-edit. Если после β пользовательский spectr покажет, что layout-toggle действительно нужен — можно вырастить до γ как следующий спринт. **α один** — недостаточно: дашборд-паттерн уже задан, на Ганте мы должны сделать как минимум то же + один шаг к unified path.

Минимальный объём первого спринта (по аналогии с Wave 1–6 дашборда):
- **Wave 1 (S):** quick-wins внутри Ганта — h2-тавтология, toolbar-divider'ы, мёртвый `#gantt-filters`
- **Wave 2 (M):** action-блок «Что требует курса в плане» наверху Ганта (без выхода в filter-bar)
- **Wave 3 (L):** общий path-shared filter-bar для 4 view'ов модуля
- **Wave 4 (M):** Гант secondary toolbar (lock-cluster / view-cluster / nav-cluster)
- **Wave 5 (S):** Motion-апгрейды в духе Wave 4 дашборда — Emerge на team-row, Pulse на overload-team

## 6. Спорные моменты и продакт-вопросы

### 6.1. h1 вкладки — «Гант по релизам» или «План квартала по релизам»?

UX-advocate (по аналогии с дашбордом «Курс квартала») за «План квартала по релизам». Дмитрий, скорее всего, за «Гант» — он привычен к этому слову.

**Моё мнение:** h1 «План квартала по релизам», eyebrow остаётся «СЛЕД ПУТИ · ГАНТ» — это удерживает brand-словарь в eyebrow, professional-словарь в h1. Best-of-both, как УЖЕ согласовано с дашборда.

**Вопрос:** ок?

### 6.2. Сколько action-cards — 0/3 или 0/5?

На дашборде согласовали top-3. Гант — power-tool, Игорь оперирует 50–80 действиями в день, **может** проглотить top-5.

**Моё мнение:** **3 + footer «Все (N) →»**. Гант-юзер уже видит overview-mode и sparkline'ы — это его «5+». Action-блок именно про «фокус», 3 — это правильно.

**Вопрос:** 3 или 5?

### 6.3. Path-shared-toolbar — на всех 4 view'ах сразу или только когда мы доделаем редизайн каждого?

Технически filter-bar можно поставить только над Гантом и Реестром на первом этапе, Канбан/Таймлайн добавить позже. Но это создаст не-консистентность в течение N недель.

**Моё мнение:** включаем shared-toolbar сразу на всех 4-х (там, где он не нужен — пустой filter-state). Без consistency cohort распадается.

**Вопрос:** все 4 сразу или только Гант + Реестр?

### 6.4. Куда деть «Подложку»?

Подложка имеет рейтинг 1.8/5 (П12 §6). Она формально модуль СЛЕД ПУТИ, но не участвует в редизайне Ганта. Если мы делаем shared-toolbar — Подложка либо тоже его получает (5-й view), либо мы её схлопываем как кандидата на удаление (П12 quick-win «Подложку — убрать в Реестр как режим группировки»).

**Моё мнение:** **исключаем Подложку из shared-toolbar.** Ставим её отдельной задачей «упразднить или объединить с Реестром» в отдельный спринт. Сейчас это шум.

**Вопрос:** ок? Или включаем 5-й tab?

### 6.5. Олеся не понимает «релизы 1.20/1.21/1.22» (П12 §5)

Это IA-проблема, но не Ганта в одиночку — она в каждом из 4-х view'ов и на дашборде. Tooltip-glossary на «1.21» с «18 мая – 14 июня · окно планирования квартала» — quick-win.

**Моё мнение:** включить в Wave 1 редизайна Ганта вместе с h2-удалением. Дешевле там, чем отдельной задачей.

**Вопрос:** делаем сейчас?

### 6.6. Toolbar — нужен ли сценарий «collapsed на overflow»?

12 кнопок + 3 кластера secondary = на 13" laptop'е может не влезть. Текущий дашборд решил это через icon-only mode для большинства. Гант secondary-toolbar тоже icon-only с tooltip'ом.

**Моё мнение:** secondary-toolbar полностью icon-only, label оставить только у `Зафиксировать план` (primary action). Tooltip для всех остальных.

**Вопрос:** ок?

### 6.7. Drop-аnimation — Pulse усиливаем (Дмитрий «silent») или оставляем Align?

Wave 4 уже добавила Align (600ms spring) и Reject (800ms). Дмитрий и Игорь жалуются «silent». Возможно, нужен ещё **Drop-Confirm Pulse** — secondary жест на dst-pill через 200ms после Align (двойной impulse).

**Моё мнение:** оставляем Align как есть, но добавляем **toast «Перенесено: BE-модель из 1.21 в 1.22»** — silent именно потому, что нет вербального подтверждения. Toast — Brand TV «Курс сверен», тот же канал. Это quick-win, не motion-апгрейд.

**Вопрос:** добавляем toast вместо/вместе с Pulse?
