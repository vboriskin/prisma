# 06 — Accessibility audit (WCAG 2.2 AA)

Scope: Сканнер команд 2.0 (`integrations/teamScanner2*.js`), Чёрный дашборд
(`integrations/blackDashboard*.js`), Settings modal + tabs
(`integrations/integrationsRenderer.js`, `views/integrationsView.js`),
CSS-правила `.ts2-`, `.bd-`, `.int-`, `.intg-`, `.signal-` в `styles.css` и
`theme.css`. Ревью построено на чтении исходников, контрасты пересчитаны
формулой WCAG (luminance ratio); APCA отмечена там где разница тонкая.

## Сводка

- Critical: **3** (form labels not associated; tertiary-text contrast on Night;
  settings modal без role/aria/Esc)
- High: **4** (light-mode signal contrast; bd-tab без role="tab"; int-modal-close
  без aria-label/type; bd-fetched/bd-header-meta caption contrast)
- Medium: **5** (BD bd-tabs без tablist semantics; int-stab без role="tab";
  link-only chevron `▸` декоративный; KPI «зелёный/жёлтый/красный» дублируют
  через class — но не через текст; int-field-input :focus убирает outline без
  visible-replacement)
- Low: **4** (`type="button"` отсутствует у некоторых button; dotStrip role="img"
  но aria-label из rich-context может быть пустым; bd-loader-hint #737373 на
  black ≈ 4.5:1 — borderline; tabindex-plan для несложных details/summary)
- Polish: **3** (skip-link для саб-таба; aria-live для `bd-fetched`; aria-current
  на активных subtab)

## Метод

- Чек-лист WCAG 2.2 AA (A–K разделы из задания) пройден по файлам
  `teamScanner2*.js` (12 файлов, ~12 700 LOC), `blackDashboard*.js`,
  `integrationsRenderer.js`, `views/integrationsView.js`, плюс CSS-локалы
  `.ts2-*` / `.bd-*` / `.int-*` / `.intg-*` / `.signal-*` в `styles.css`
  (≈1 176 base rules) и `theme.css`.
- Контраст пересчитан формулой WCAG `((c+0.055)/1.055)^2.4` per channel,
  Y = 0.2126·R + 0.7152·G + 0.0722·B, ratio = (L1+0.05)/(L2+0.05).
- Brandbook §3 палитра проверена в обоих режимах (`[data-theme="dark"]`,
  `[data-theme="light"]` и легаси-класс `body.theme-dark`).

## Находки

### F1 — `--prizma-text-tertiary` `#5A5A64` на Night ≈ 2.96:1 [Critical]

**WCAG:** SC 1.4.3 Contrast (Minimum) AA — normal text 4.5:1, large text 3:1.

**Где:** `theme.css:26` объявляет `--prizma-text-tertiary: #5A5A64` на Night
`#0A0A0F`. Этот токен подкладывается под `--text-3` и `--text-4` (`styles.css:168-169`).
Используется в малом тексте (10–12px) во множестве `.bd-*` / `.int-*` /
`.ts2-*` правилах:

- `.bd-fetched` 11.5px (`styles.css:11589`)
- `.bd-header-meta` 12px (`:11588`)
- `.bd-kpi-lab` 11.5px (`:11701`)
- `.bd-team-mini` 11px (`:11738`)
- `.bd-issue-type` 10.5px (`:11751`)
- `.bd-cov-pk` 10.5px (light-mode default, `:11787-91`)
- `.bd-state-sub` 12.5px (`:11840`)
- `.bd-more` 11px (`:11821`)
- `.int-status-count/sync/none` 11–12px (`:9497-501`)
- `.int-empty-sub` 12.5px (`:11055`)
- `.int-field-hint` 11px (`:11171`)
- `.int-field-hint-inline` 11px (`:11174`)
- `.int-subblock-hint` 11.5px (`:11577`)
- `.ts2-action-queue-hint` 11px (`:12580`)
- `.ts2-zombie-hint/-status` 11px (`:12644-62`)
- `.bd-diag-err-more`, `.bd-diag-rule-row` (диагностика BD)

**Расчёт:** `#5A5A64` → Y ≈ 0.108. `#0A0A0F` → Y ≈ 0.0033.
Контраст = (0.108+0.05) / (0.0033+0.05) = 0.158 / 0.0533 = **2.96:1**.
Не проходит даже large-text (3:1).

В light режиме `--prizma-text-tertiary: #B5B5BC` на `#FAFAF8` даёт
**1.97:1** — ещё хуже (FAIL для всех размеров).

**Рекомендация:** Поднять `--prizma-text-tertiary` для тёмной темы до
`#7A7A82` или `#8A8A92` (≈4.5:1 — passes small-text). Для светлой —
до `#85858E` (≈4.6:1 на `#FAFAF8`). Bb V21 Wave-3 уже подняли
`--prizma-text-secondary` (`#8E8E96`) — нужно тот же приём для tertiary.
Альтернатива: выделить `--prizma-text-caption` как самостоятельный
семантический токен и оставить tertiary только для UI-borders /
неинформативных глифов (≥3:1 как UI-component).

**Цена:** S (один токен на тему + auto-тема).

### F2 — Form labels не связаны с инпутами в settings-modal [Critical]

**WCAG:** SC 1.3.1 Info and Relationships, SC 4.1.2 Name, Role, Value.

**Где:** `integrations/integrationsRenderer.js:41–127` — все 14 input-полей
имеют `<label class="int-field-label">…</label>` БЕЗ `for=` и БЕЗ оборачивания
инпута. Пример:

```html
<label class="int-field-label">Endpoint (Base URL)</label>
<input class="int-field-input" id="int-jira-url" type="url" …>
```

Screen-reader не находит programmatic name; user будет слышать
"edit, blank" без подписи. Касается Jira Delta, Jira Sigma, Bitbucket,
Confluence (Endpoint, Token, Project Keys, Space Keys, окно часов).

**Исключение:** `:167` `<label … for="int-global-since-date">` —
единственный label с правильной связью.

**Рекомендация:** Добавить `for="${inputId}"` на каждый `<label>`. Inputs
уже имеют id. Минимально: `<label class="int-field-label" for="int-jira-url">`.
ИЛИ wrap: `<label class="int-field-label">Endpoint <input id="int-jira-url" …></label>`.

**Цена:** S (механическая правка ~14 строк в renderer).

### F3 — Settings modal без role="dialog" / aria-modal / Esc / focus-trap [Critical]

**WCAG:** SC 4.1.2 Name, Role, Value; SC 2.1.1 Keyboard; SC 2.4.3 Focus Order;
SC 2.1.2 No Keyboard Trap.

**Где:** `integrations/integrationsRenderer.js:23` —
`<div class="int-modal-overlay" id="int-settings-modal"><div class="int-modal-box">`
без `role="dialog"`, без `aria-modal="true"`, без `aria-labelledby`.

`views/integrationsView.js:88–122` (`bindSettingsModal`) — нет:
- слушателя `keydown` Escape для закрытия,
- focus-trap (Tab за пределы модалки уходит в основной контент),
- начального фокуса (фокус остаётся на triggering элементе под overlay'ем),
- возврата фокуса на trigger при закрытии (`modal.remove()` без
  `prevTrigger.focus()`).

Сравните: `teamScanner2.js:1416–1430` — корректный focus-trap для ts2-panel
(`role="dialog" aria-modal="true"` в `teamScanner2Renderer.js:2851`,
плюс Escape + Tab guard).

**Рекомендация:**
1. На `<div class="int-modal-overlay">` добавить `role="dialog"`,
   `aria-modal="true"`, `aria-labelledby="int-modal-title"`.
2. `<span class="int-modal-title">` → `<h2 id="int-modal-title">` (или
   `id="int-modal-title"` на span с aria-level).
3. В `bindSettingsModal()` после insertion: `firstFocusable.focus()`,
   `trigger = document.activeElement` сохранить, повесить `keydown`
   Escape → `close()`, Tab → trap (как в ts2).
4. В `close()`: `trigger?.focus()`.

**Цена:** M (3–5 строк HTML + 25–40 строк JS focus-management).

### F5 — `int-modal-close` без aria-label / type / aria-hidden на иконке [High]

**WCAG:** SC 4.1.2; SC 1.1.1 Non-text Content (icon-only button).

**Где:** `integrations/integrationsRenderer.js:20`:
```html
<button class="int-modal-close" id="int-modal-close">✕</button>
```

- Отсутствует `aria-label` — SR прочтёт literal Unicode символ "X" или
  ничего, если глифа нет в lookup.
- Отсутствует `type="button"` — внутри `<form>` мог бы submit'ить
  (в данном случае модалки нет form, но defensive practice).
- Глиф не обёрнут в `<span aria-hidden="true">`.

**Рекомендация:**
```html
<button class="int-modal-close" id="int-modal-close" type="button"
        aria-label="Закрыть настройки"><span aria-hidden="true">✕</span></button>
```

**Цена:** XS (одна строка).

### F6 — `bd-tab` / `int-stab` / `int-subtab` без `role="tab"` + `aria-selected` [High]

**WCAG:** SC 4.1.2; SC 1.3.1.

**Где:**
- `blackDashboardRenderer.js:204-206` — `<div class="bd-tabs">` + `<button
  class="bd-tab bd-tab-active">` без `role="tablist"`, `role="tab"`,
  `aria-selected="true|false"`, `aria-controls=""`.
- `integrations/integrationsRenderer.js:30-35` — `<div class="int-settings-tabs">`
  + `<button class="int-stab active">` — то же.
- `views/integrationsView.js:551-554` — `<div class="int-subtabs">` +
  `<button class="int-subtab int-subtab-active">` — то же.

Сравните: `teamScanner2Renderer.js:317-320, 320-322` — `<div role="tablist">`
+ `<button role="tab" aria-selected="${...}">` корректно.

Без role tab pattern, screen-reader не различает «таб» и обычную кнопку,
не озвучивает «selected» state, не позволяет arrow-keys между табами.

**Рекомендация:** Привести 3 саб-таб группы к ts2-паттерну:
```html
<div class="int-subtabs" role="tablist" aria-label="Разделы интеграций">
  <button class="int-subtab" role="tab" aria-selected="true|false"
          aria-controls="int-panel-scanner2" id="int-tab-scanner2">…</button>
</div>
<div id="int-panel-scanner2" role="tabpanel" aria-labelledby="int-tab-scanner2">…</div>
```
Plus arrow-key handler в bindings (Left/Right move active, Home/End → first/last).

**Цена:** S–M (по 5–10 строк на каждую группу + общий arrow-key handler).

### F7 — `.int-field-input:focus { outline: none; }` без замены [High]

**WCAG:** SC 2.4.7 Focus Visible AA; SC 1.4.11 Non-text Contrast.

**Где:** `styles.css:11169` — `.int-field-input:focus { outline: none;
border-color: var(--prizma-information); }`.

Замена — только border-color. Border ширина `1px` (`:11154` примерно), и
изменение цвета даёт контраст border-vs-background ≈3:1, но в WCAG SC 1.4.11
уточнено: focus indicator должен иметь 3:1 vs adjacent colour AND ≥2 CSS px
тонкости. Тонкая 1px-граница на чёрном фоне в дарке плохо видна.

**Рекомендация:**
```css
.int-field-input:focus,
.int-field-input:focus-visible {
  outline: 2px solid var(--prizma-information);
  outline-offset: 1px;
  border-color: var(--prizma-information);
}
```

То же касается `.assistant-fab:focus-visible { outline: none; box-shadow: ... }`
(`:4357`) — box-shadow ring как `0 0 0 3px` идёт, но проверить, что есть
3:1 vs adjacent. Minor — можно объединить в шаблон `--prizma-focus-ring`.

**Цена:** S (~2 правила в CSS).

### F8 — Coverage bars / KPI «зелёный/жёлтый/красный»: цвет несёт основной смысл [Medium]

**WCAG:** SC 1.4.1 Use of Color.

**Где:** `blackDashboardRenderer.js:340-345` —
```html
<div class="bd-cov-fill bd-kpi-green|yellow|red" style="…">…</div>
```
+ числовая статистика рядом (`{linked}/{total} ({pct}%)`). Числа
дублируют смысл — ОК для нашего паттерна.

Однако `.bd-kpi-green/yellow/red` сами по себе (в `.bd-kpis` ряду) не
содержат текстовой подсказки «нормально/плохо». Например, `.bd-kpi-green
.bd-kpi-val=85% .bd-kpi-lab="Покрытие"` — пользователь с дальтонизмом
видит зелёный фон как оттенок без semantic. Но число читается.

**Где marginal:** `.bd-cov-fill` — width-bar, ширина=`(linked/total)·100%`
+ цвет = категория. Узкая тёмная полоска с зелёным цветом vs красным —
дальтоник видит «narrow polosa» одного оттенка, отличие от 30% к 70%
видно по ширине, но категоризация (good/bad) — теряется.

**Рекомендация:** Добавить text-marker рядом с pct в bd-cov-row:
- ≥70%: ✓ (или текст "ок")
- 40–69%: ! (внимание)
- <40%: ⚠ (риск)

ИЛИ — иконка в `.bd-cov-fill::before` (status glyph, разной формы для
разных классов: круг/треугольник/квадрат).

**Цена:** S (3 строки HTML + CSS на icon-via-pseudo).

### F9 — `bd-meme` decorative без `aria-hidden` на root [Medium]

**WCAG:** SC 1.1.1 Non-text Content (decorative).

**Где:** `blackDashboardRenderer.js:633` —
```html
<div class="bd-meme-face" aria-hidden="true">
  <div class="bd-meme-eye …"></div>
  <svg class="bd-meme-grin" aria-hidden="true">…</svg>
</div>
```

`aria-hidden="true"` на root face — ОК. Но дочерние `.bd-meme-eye`
(2 div'а) не имеют aria-hidden (наследуется от parent — это работает),
а сам loader-status/phrase **не имеет `role="status"` / `aria-live="polite"`**
для динамических обновлений.

`#bd-loader-status` обновляется каждые 2 секунды функционально (elapsedMs).
`#bd-loader-phrase` rotate'ит юмор-фразу каждые 2.6с.

**Рекомендация:** Добавить `role="status" aria-live="polite"` на
`#bd-loader-status` (functional info). Phrase — `aria-hidden="true"`
(юмор не должен спамить SR каждые 2.6с).

**Цена:** XS (2 атрибута).

### F13 — Bd-meme animations всегда running [Low]

**WCAG:** SC 2.3.3 Animation from Interactions (AAA, не AA — но best practice).

**Где:** `styles.css:10485, 10507, 10527` — `bd-meme-sway`, `bd-meme-blink`,

fade-in оставался. Тоже самое для `.bd-meme-eye` blink.

### F16 — `dotStrip` SVG aria-label может быть пустым [Low]

## Quick a11y wins без потери функционала

(5–10 пунктов: 1–2 строки CSS/HTML, ничего не ломают)

1. **`int-modal-close` aria-label** — одна строка:
   ```html
   <button class="int-modal-close" id="int-modal-close" type="button"
           aria-label="Закрыть настройки"><span aria-hidden="true">✕</span></button>
   ```
   (`integrations/integrationsRenderer.js:20`)

2. **role="dialog" + aria-modal на settings-modal-overlay**:
   ```html
   <div class="int-modal-overlay" id="int-settings-modal"
        role="dialog" aria-modal="true" aria-labelledby="int-modal-title">
   ```
   + сменить `<span class="int-modal-title">` → `id="int-modal-title"`.
   (`integrations/integrationsRenderer.js:23, 20`)

3. **Esc handler на settings-modal** — добавить в `bindSettingsModal()`:
   ```js
   const onEsc = (e) => { if (e.key === 'Escape') close(); };
   document.addEventListener('keydown', onEsc);
   // в close() — document.removeEventListener('keydown', onEsc);
   ```
   (`views/integrationsView.js:106-110`)

4. **role="status" aria-live на bd-loader-status**:
   ```html
   <div class="bd-loader-status" id="bd-loader-status"
        role="status" aria-live="polite">…</div>
   ```
   (`integrations/blackDashboardRenderer.js:669`)

5. **role="progressbar" на bd-cov-track**:
