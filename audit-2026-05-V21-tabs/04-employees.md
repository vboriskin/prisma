# Аудит вкладки «КОМАНДА · СОТРУДНИКИ» — V21 tabs

**Дата:** 2026-05-05
**Скоуп:** `views/employees.js`, `#section-employees` в `index.html`, `.employees-*` / `.emp-*` / `.kpi-*` правила в `styles.css`, `EmployeeFactory` в `rowFactory.js`.
**Базовый фидбэк юзера:** «заполнение сотрудников выглядит как-то не очень красиво».
**4 эксперта:** UX/Form, Visual/Brand, Identity contract, Domain HR/load.

---

## TL;DR

«Формы сотрудника» как самостоятельной сущности **в проекте нет**. Кнопка `+ Сотрудник` в `app.js:1082-1090` просто **пушит пустой объект** в `state.employees` и вызывает `EmployeesView.render()` — пользователь редактирует появившуюся карточку in-place. Это и есть «форма»: сама карточка работает одновременно как read-view, edit-view и delete-target. Отсюда «не очень красиво» — карточка спроектирована для *просмотра* (header + meta + footer), а заполнение нового сотрудника происходит в той же сетке `90px | 1fr` в гриде по 3 в ряд, и юзер видит пустое поле ФИО среди 8 других пустых полей без визуальной приоритизации того, **что заполнять сейчас**.

Дальше — 16 пунктов с severity и предложение редизайна.

---

## Находки

### 1. [HIGH · UX] Создание сотрудника не открывает форму, сразу мутирует state
**Файл:** `app.js:1081-1090`
**Что:** клик `+ Сотрудник` → `state.employees.push(EmployeeFactory.create({sourceType:'manual'}))` → `render()`. Никакой модалки, никакого фокуса на ФИО, никакого «Сохранить/Отмена».
**По-человечески:** жмёшь кнопку — внезапно появляется пустая карточка где-то в гриде (сортировка по ФИО → у новой пустой fio='' она идёт вверх или вниз непредсказуемо), фокус не выставлен, history checkpoint уже сделан, пустые сотрудники накапливаются если пользователь нажал случайно. Это не «добавление», это «вставка дефолтного row + редактируй где найдёшь».
**Предложение:** открыть **слайд-овер справа** или модалку с минимальным контрактом (ФИО + Команда + Роль + опционально email) и кнопками Сохранить / Отмена. Только после Сохранить — push в state. ФИО получает auto-focus.

### 2. [HIGH · UX] Каждое изменение поля делает full re-render всей вкладки
**Файл:** `views/employees.js:330-338, 392-401, 402-411, 438-444, 453-463, 466-474`
**Что:** в `_buildFioInput`, `_buildRolesInput`, `_buildTeamsInput`, `_buildOtDaysControl`, `_buildWeekdayCheckbox`, `_buildWeekdayCommentInput` — все handler'ы вызывают `EmployeesView.render()`.
**По-человечески:** ввёл символ в ФИО → blur → весь grid карточек перерисовался, фокус потерян, скролл прыгнул. На 50+ сотрудниках это заметная пауза. Уже есть `_buildIdInput` (строка 347-367), который правильно избегает re-render — паттерн рабочий, но не растиражирован.
**Предложение:** только `_buildFioInput` (нужен для пересортировки) и `_buildRolesInput`/`_buildTeamsInput` (нужны для пересборки списка фильтров) обязаны re-render. OT-чекбокс / weekday / комментарий — local DOM update без render.

### 3. [HIGH · Visual/Brand] Карточка-просмотр и карточка-форма — одно и то же
**Файл:** `views/employees.js:655-773`, CSS `styles.css:3291-3354`
**Что:** одна и та же `.employee-card` показывает: header (FIO + delete), 7 row'ов (Роль, Команда, Дни OT, Будни, Нагрузка, +4 identity), advanced details, footer с метой. Всё в гриде `90px label | 1fr value`.
**По-человечески:** при заполнении нового — 8 пустых полей без иерархии: какие обязательны, какие опциональны, какие — для интеграций. Брендбук Призмы требует Spine-pill дисциплины (3px stripe-left, CAPS sub-headers). Карточка её соблюдает по типографике, но не по информационной иерархии.
**Предложение:** разделить **режимы** карточки — `mode="view"` (свёрнутая, показывает FIO + role + team + load) и `mode="edit"` (раскрытая форма с группами). Клик по карточке — переход в edit. Spine 3px-stripe слева на edit-карточке.

### 4. [HIGH · Identity] Identity-секция растёт ниже сгиба и кажется мусорной
**Файл:** `views/employees.js:719-726`, CSS `styles.css:3335-3340`
**Что:** 4 поля идентификации (Email, Jira accountId, Bitbucket login, Confluence accountId) лежат под подзаголовком «Идентификация для интеграций» в той же сетке. Пользователь должен ввести 4 непохожих идентификатора без понимания «зачем какой».
**По-человечески:** пилот обратной связи (V20 S8 #11) уже вернул эту проблему по service-account toggle: «toggle для разработчика, не для меня». То же тут — Jira accountId типа `5b10a2844c20165700ede21g` отпугивает HR-юзера. Hint скрыт в `title=""` (строки 723-726), а не виден сразу.
**Предложение:** свернуть identity-секцию в `<details>` «Привязка к интеграциям (опционально)». Email вынести **наверх** карточки рядом с ФИО — он реально нужен (resolve Confluence accountId, fuzzy-fallback). Остальные 3 — внутри collapsible с пояснением «заполнится автоматически после первого PR/комментария» или «оставьте пустым, если человек не использует Bitbucket/Jira/Confluence».

### 5. [HIGH · UX] Нет inline-валидации, дубликатов, пустых ФИО
**Файл:** `views/employees.js:330-336`, `rowFactory.js:127-147`
**Что:** `EmployeeFactory.normalize` делает trim, но не проверяет дубликат по ФИО / email, не валидирует email (regex), не предупреждает о пустом ФИО.
**По-человечески:** можно создать 5 пустых карточек подряд, они нормализуются в 5 сотрудников с пустым `fio`. Bug 5 минут спустя: «почему сводка показывает 47 сотрудников, в реальности 42?». В `mergeImported` (`employees.js:803-837`) merge по ФИО есть, в UI add — нет.
**Предложение:**
- При сохранении блокировать пустой ФИО.
- Показывать warning-pill «такое ФИО уже есть» при коллизии.
- Email — валидировать regex и приводить к lowercase (уже делается в normalize, но юзер не видит).

### 6. [MED · UX] Импорт CSV/XLSX использует `confirm()` вместо ConfirmDialog
**Файл:** `views/employees.js:831`
**Что:** `const ask=confirm('${sourceLabel}: добавить N, обновить M. Применить?');` — native browser dialog.
**По-человечески:** в проекте уже есть `ConfirmDialog` (используется в `_buildDeleteButton`, строка 508), даёт focus-trap, danger-стиль, keyboard-friendly. А импорт сотрудников ломает паттерн.
**Предложение:** заменить на `ConfirmDialog.show({title:'Применить импорт?', message:..., confirmLabel:'Применить'})`. И добавить **превью**: показать первые 5 imported rows перед confirm.

### 7. [MED · Visual] Footer-meta `source: manual` и id-хеш светятся в каждой карточке
**Файл:** `views/employees.js:752-761`, CSS `styles.css:3341-3348`
**Что:** футер «source: manual · создан: 02.05.2026» в каждой карточке, monospace.
**По-человечески:** для пользователя это шум. Для дебага полезно, но в обычном режиме карточка перегружена «техникой».
**Предложение:** скрыть футер за hover или в `<details>` «Дополнительно». Опционально показывать source только если он **не** `manual` (чтобы видно было «привезён из CSV»).

### 8. [MED · Domain] OT-дни добавляются по одной дате, без диапазонов
**Файл:** `views/employees.js:412-452`
**Что:** `_buildOtDaysControl` — input type=date + кнопка `+`, чипы ниже.
**По-человечески:** если человек овертаймит выходные 2 недели подряд — 14 кликов. Реальный сценарий «эта суббота и воскресенье каждой недели июня» нерешаем без 8 кликов.
**Предложение:**
- Поддержать диапазон: `<input type="date" from> — <input type="date" to>`, кнопка `+` добавляет все даты в диапазоне.
- Опционально пресет «все субботы месяца», «все выходные релиза 1.21».
- Чипы группировать по месяцам с числом «5 дней в июне», expand на клик.

### 9. [MED · Domain] `weekdayReady` без контекста — что значит «готов в будни»?
**Файл:** `views/employees.js:453-463`, `index.html:1117` (нет легенды)
**Что:** чекбокс «Готов в будни» + рядом тег-input «Комментарий к будням». Брендового объяснения нет.
**По-человечески:** «готов в будни» — на фоне OT-дней звучит будто «человек готов работать в будние дни» (тавтология). Реально означает «готов остаться сверх 8 часов в будни» (овертайм по будням, в отличие от выходных). Без подсказки путаница гарантирована.
**Предложение:** переименовать в **«Овертайм по будням: готов»** + tooltip «может задержаться сверх 8 часов в будний день». А поле комментария оформить как «когда не может» (даты/недели исключений).

### 10. [MED · UX] Tag-input для weekdayComment — неправильный паттерн
**Файл:** `views/employees.js:466-474`
**Что:** `createTagInput` для weekdayComment — это free-text комментарий, а не tags.
**По-человечески:** юзер ожидает text-area / input. Получает chip-style ввод, разделённый по `|`/`,`. Если хочет написать «не может во вторник 5 мая, заболел ребёнок» — запятая разорвёт на чипы.
**Предложение:** поменять на обычный `<textarea>` или `<input type="text">`. Tag-input оставить только для roles/teams, где это действительно множества.

### 11. [MED · Brand] KPI-карточки и сводка по командам не следуют 3px-stripe-spine
**Файл:** `views/employees.js:244-250` (kpi summary), 295-317 (teams summary)
**Что:** `kpi-card kpi-signal-on-course` etc. рендерятся стандартно. Сводка по командам — обычная `data-table` без spine-полоски. CLAUDE.md явно требует «3px stripe-left для активных/выделенных элементов вместо filled background».
**По-человечески:** загруженный сотрудник в `_renderLoadSummary` (строка 603-647) **уже** правильно использует `border-left-color: red/amber/green` (Spine-стиль) — но KPI-карточки выше используют старый паттерн с filled background через `kpi-signal-*`. Несогласованность визуального языка.
**Предложение:** перевести `.kpi-card.kpi-signal-*` на `border-left: 3px solid var(--prizma-...)` без заливки background. Сводка по командам — добавить stripe-left на ряды с риском (>0 блокеров / OT).

### 12. [MED · UX] Mobile/responsive: грид на 380px ломается на смартфонах
**Файл:** `styles.css:3291-3294` `grid-template-columns: repeat(auto-fill, minmax(380px, 1fr));`
**Что:** на 360px-экранах одна карточка горизонтально не помещается без overflow. Внутри карточка — `90px label | 1fr value`, дата OT-input min-width 160px.
**По-человечески:** на мобиле всё либо обрезано, либо горизонтальный скролл. Tools-bar (`employees-controls`) тоже не схлопывается.
**Предложение:** breakpoint `<768px`:
- `grid-template-columns: 1fr` (одна карточка в ряд, full width).
- Внутри карточки `display:flex; flex-direction:column` для row'ов (label сверху, value снизу).
- Tools-bar в `<details>` «Фильтры».

### 13. [LOW · UX] Кнопки в section-header (`+ Сотрудник`, XLSX, CSV, Шаблон, Удалить всех) не группируются
**Файл:** `index.html:1104-1114`
**Что:** 5 кнопок подряд, две из них — обёрнутые `<label>` с скрытым input, между ними нет логической группировки. Эмодзи 📄 в шаблоне противоречит правилу «без эмодзи в production UI» (CLAUDE.md § Принципы дизайна).
**По-человечески:** «Удалить всех» рядом с «Шаблон» — danger-кнопка не отделена. Шаблон с эмодзи смотрится out-of-brand.
**Предложение:**
- Группа «Добавить»: `+ Сотрудник` | dropdown «Импорт ▾» (CSV / XLSX / Шаблон).
- Danger-кнопка «Удалить всех» — отделить spacer'ом справа.
- Убрать эмодзи 📄, заменить на icon из `Icons.get('download')`.

### 14. [LOW · Domain] Capacity по умолчанию 5 захардкожена в `_renderLoadSummary`
**Файл:** `views/employees.js:619` `const cap = emp.capacity || 5;`
**Что:** capacity не отображается в карточке, не редактируется юзером, default 5 — магическая константа.
**По-человечески:** «нагрузка» считается относительно невидимого capacity=5. Если у тимлида capacity реально 3 — всё равно зелёным до 4 задач.
**Предложение:** добавить поле `capacity` в карточку (рядом с роль/команда), default 5, числовой ввод 1..10. Показывать рядом со sparkline нагрузки.

### 15. [LOW · UX] Сортировка только по 4 полям, нет поиска по ФИО
**Файл:** `views/employees.js:139-145, 191-202`
**Что:** controls-bar предлагает только sort и filter team/role/OT. На 50+ сотрудниках не найти конкретного без скроллинга или filter-by-team.
**Предложение:** добавить `<input type="search" placeholder="Поиск по ФИО">` в controls-bar, debounce 200ms.

### 16. [LOW · Identity] Auto-resolve confluence по email тихо срабатывает
**Файл:** `views/employees.js:370-391`
**Что:** при заполнении email система делает fire-and-forget POST `/api/integrations/confluence-resolve-user` и при success — заполняет confluenceAccountId + toast + re-render.
**По-человечески:** хорошая фича, но:
- юзер не знает, что это произойдёт (нет hint'а на email-поле «после ввода попробуем подтянуть Confluence»);
- re-render перетряхивает grid;
- нет «отменить» — если auto-resolve взял не того человека (омонимы), юзер должен **вручную стереть**.
**Предложение:** показать спиннер у поля Confluence во время запроса; toast с CTA «Это не он? отменить»; hint «после ввода попробуем подтянуть Confluence/Jira».

Цель: разделить «просмотр» и «заполнение», сделать ввод нового сотрудника понятным с первого взгляда, спрятать identity-поля под пояснение «опционально, для интеграций».

### Группы

| Группа | Поля | Обязательные | Видимость |
|--------|------|--------------|-----------|
| 1. Основное | ФИО, Email | ФИО | всегда |
| 2. Команда и роль | Команда, Роль, Capacity | — | всегда |
| 3. Овертайм | weekdayReady, overtimeDays (range), weekdayComment | — | всегда |
| 4. Привязка к интеграциям | jiraAccountId, bitbucketLogin, confluenceAccountId, isServiceAccount | — | `<details>` свёрнуто |
| 5. Мета | source, createdAt, updatedAt | — | hover/footer/dev-only |

### Edit vs add

- **Add** (кнопка `+ Сотрудник`) — открывается slide-over с пустыми полями, ФИО auto-focus, Сохранить блокируется пока ФИО пуст.
- **Edit** (клик по карточке) — тот же slide-over, поля заполнены, Сохранить превращается в «Готово», есть кнопка «Удалить» (danger, через `ConfirmDialog`).
- **View** (карточка в гриде) — компактная: ФИО large, Команда·Роль каноном, Spine-stripe-left (зелёный/amber/red по нагрузке), маленький badge `OT: 5` если есть овертайм, identity-поля **не отображаются** (только при наличии всех 4 — иконки 🟢/⚪ в углу для интеграций; иконки можно через `Icons.get`, не как emoji-в-тексте).

### Inline-edit FIO?

Оставить inline-редактирование **только** для ФИО (двойной клик по строке ФИО в карточке) — частая операция исправления опечаток. Всё остальное — через slide-over.

### Импорт CSV/XLSX

- Объединить кнопки в dropdown `Импорт ▾` (п.13).
- Превью первых 5 строк перед merge (п.6).
- Заменить `confirm()` на `ConfirmDialog` (п.6).

### Что точно убрать

- Эмодзи 📄 в шаблоне (`index.html:1112`).
- `emp-load-chip` цвета не из brand-палитры (`styles.css:5443-5446`) — заменить на `var(--prizma-...)`.
- Re-render всей вкладки при каждом change (п.2).
