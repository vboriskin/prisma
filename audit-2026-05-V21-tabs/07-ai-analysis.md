## Эксперт 1 — Visual / Brand

1. **Заголовок страницы содержит emoji-«робота» 🤖.**
   `aiRenderer.js:356`: `<h2 class="ai-page-title">🤖 Центр AI-аналитики</h2>`.
   Прямое нарушение § «Принципы дизайна» в `CLAUDE.md` («Без эмодзи в production
   UI»). Заменить на иконку `Icons.hydrate` с восьмилучевой звездой или знаком
   `sparkle` (см. раздел «Иконка-замена»).

2. **AI-enhanced-badge — sparkle-emoji ✨.**
   `aiRenderer.js:46`: `<span class="ai-enhanced-badge">✨ AI</span>`. Тоже emoji
   в проде. Брендбуковый аналог — мини-звезда 8×8 (тот же восьмилучевой глиф,
   уменьшенная сборка).

3. **Цветные «🔴 / 🟡 / 🔵» круги в Health-блоке.**
   `aiRenderer.js:96`: `p.severity==='critical'?'🔴':p.severity==='warning'?'🟡':'🔵'`.
   Семантически дублирует `.ai-sev-*` stripe-left (3px) и брендовые токены
   состояний — выкинуть emoji полностью, оставить stripe.

4. **Loader использует ⏳.**
   `aiRenderer.js:328`: `<span class="ai-block-icon">⏳</span>`. Заменить на
   `inlinePulseLoader` из `app/prizmaUI.js` (он уже соответствует брендбуку).

5. **Хардкод hex-палитры обходит дизайн-токены.**
   `styles.css:7236–7253` и `7293–7349`: `#dcfce7`, `#fee2e2`, `#fef3c7`,
   `#ef4444`, `#f59e0b`, `#22c55e`, `#3b82f6`, `#dbeafe`, `#1e3a8a` — всё
   зашитыми константами Tailwind-палитры. Нужна замена на `--prizma-success-*`,
   `--prizma-danger-*`, `--prizma-warning-*`, `--prizma-information-*` (они уже
   есть в `theme.css`, см. использование в `.ai-prio-num`).

6. **Status-badges используют filled-background.**
   `.ai-status-ok/.ai-status-risk/.ai-status-critical` (строки 7236–7240) —
   контрастные пилюли с заливкой. По брендбуку для активных состояний должен
   использоваться **3px stripe-left** + неон-акцент. Сейчас filled пилюли
   корректны как «бейджи» (это не nav-item), но сама палитра нарушает
   принцип «accent — semantic only»: для info-блока используется чистый
   `#dbeafe/#1e3a8a`, не `--prizma-information-bg`.

7. **`.ai-status-warning` мёртвый класс.**
   `styles.css:7238`: `.ai-status-warning` определён, но в `STATUS_CLASS`
   (`aiRenderer.js:17`) его нет — в коде `risk` мапится на `ai-status-risk`,
   а `warning` приходит только в `SEV_CLASS` для problem-items. Расхождение
   таксономий → стиль не применяется.

## Эксперт 3 — Frontend / HTML / a11y

10. **Семантика заголовков сломана.**
    `aiRenderer.js:356` использует `<h2>` для page-title, а каждый блок —
    `<h3>` (`aiRenderer.js:43`). Но `index.html` для секции
    `#section-ai` пустой контейнер, и нет `<h1>` страницы Призмы (тайтл App).
    В `aria-`иерархии скрин-ридер услышит h2 без h1. Стоит либо понизить
    page-title до `<h1>` (если это «страница» в SPA-смысле), либо добавить
    visually-hidden h1.

11. **Ни одна кнопка не имеет `aria-label`.**
    `aiRenderer.js:57–62` — `Показать задачи`, `Объяснить`, `↺ Обновить
    AI-анализ`, `↺ Обновить всё`. Текстовая метка есть, но `↺` — это символ
    «counterclockwise gapped circle arrow» (читается screen-reader'ом как
    «counterclockwise»), для русского пользователя бессмысленно. Заменить
    на иконку `rotate-cw` из `Icons` (как уже сделано в `aiView.js:201`
    после клика — но в первоначальном рендере `↺` остаётся unicode).

12. **`renderEmptyState` без role.**
    `aiRenderer.js:337–343` — div без `role="status"` или `aria-live`.
    Когда фильтр обнуляет рекорды и пользователь видит «Нет данных для
    анализа», скрин-ридер ничего не объявит.

13. **Memory-leak ловушка уже есть, но JSON-инъекция нет.**
    `aiRenderer.js:84` и `:98`:
    `data-filter='${JSON.stringify(r.filter)}'` без `escapeHtml`. Если в
    rule-based recommendation попадёт значение с одинарной кавычкой
    (например имя релиза `Q4 'overtime'`) — атрибут поломается. Контракт
    `_blocks` сейчас детерминирован, но при LLM-output (`applyLLMResult`)
    `recommendations[].filter` зануляется (`r.filter = null`, строка 105
    `aiView.js`) — поэтому риск низкий, но защиту добавить надо.

14. **`onclick = …` overwrite-pattern в `_bindEvents`.**
    `aiView.js:187` — комментарий объясняет, что это спасает от memleak. Это
    ОК, но `e.target.id === 'ai-refresh-all'` ломается, если event-target —
    inline-loader (внутри `<button>`). После клика по `inlinePulseLoader`
    SVG `e.target` будет `<svg>`/`<circle>`, а не сам `<button>`. Должно быть
    `e.target.closest('#ai-refresh-all')`.

15. **`renderBlockLoading` возвращает выражение, которое потом обрезается
    регуляркой.** `aiView.js:243`:
    `renderBlockLoading(...).replace(/^<div[^>]*>|<\/div>$/, '')` — снимает
    обёртку, оставляет внутренности и вставляет в существующий
    `#ai-block-${id}`. Это хрупко: если в `renderBlockLoading` появится
    второй `</div>` в конце (например wrap), регулярка съест не тот тег.
    Лучше — `renderBlockInner(blockId, title)` без обёртки.

16. **`section#section-ai > #ai-root` дублирует ARIA-структуру.**
    В `index.html:1184–1186` уже есть `id="ai-root"`. В `aiView.js:166,177`
    рендер пишет ещё один `<div id="ai-root">`. Получается `#ai-root > #ai-root`
    — два элемента с одним и тем же id, валидация HTML падает.

## Эксперт 4 — UX / Product

17. **«Прогноз курса» обещан, не дан.**
    Заголовок страницы (V21 ребрендинг): «Прогноз курса: «Если ничего не
    менять»» — этот sub задаётся через `renderPageHeader('ai', { sub: ... })`
    (`aiView.js:164`). Но дальше структура — `health → forecast →
    if_nothing_changes → dashboard → quality → bottlenecks → anomalies →
    risk_narrative → second_opinion → prioritization → dependency →
    replanning → recommendations` — 13 блоков плотным массивом. Ни одного
    видимого «курса» (трендовой кривой, проекции по неделям). Прогноз
    релизов (`forecast`) — это горизонтальные бары без оси времени.
    Тимлид ожидает (по фидбэку): «прогноз курса» = временна́я кривая
    «как изменится done% к концу спринта/квартала», а не пилюли.

18. **Нет autoplay-симуляции «Если ничего не менять».**
    `if_nothing_changes` блок отдаёт текстовый список последствий (insights/
    recs). Пропущена ключевая фича: интерактивный slider «через N недель»
    или анимация-таймлайн. Это самый ценный сценарий для тимлида —
    «покажи в видео-формате, что произойдёт».

19. **Слишком много блоков — нет приоритизации внимания.**
    13 блоков в layout 1 → 2col → 2col → 2col → 2col → 2col → 2col → 1.
    Когнитивная нагрузка перегружена. Health и Quality дублируют друг
    друга (оба дают score 0–100). Bottlenecks/Risk_narrative/Second_opinion —
    три «что не так с планом» секции. Стоит провести кластеризацию:
    «Сейчас» / «Завтра» / «Что делать», или ввести табы поверх grid.

20. **`Обновить всё` — sequential await в цикле.**
    `aiView.js:286–296` — `for (const id of ids) await callBlockLLM(...)` =
    13 последовательных запросов к LLM-proxy. На 800 токенов и temperature
    0.25 это 1.5–2 минуты ожидания. Page-loader блокирует UI всё время.
    Нужен либо `Promise.all` с rate-limit, либо progressive-fill (по мере
    готовности — рендерить отдельные блоки).

21. **Нет «копировать как отчёт».**
    Тимлид показывает данные руководству. Нужна кнопка «Скопировать как
    Markdown» / «Экспорт в Confluence», агрегирующая `summary` + top-3
    `insights` каждого блока. Сейчас можно нажать только «Объяснить»
    отдельный блок.

22. **Нет истории прогнозов.**
    AI-анализ stateless. Если обновить «всё» в понедельник и в пятницу —
    нельзя сравнить, как изменился `health.score`. Нужен временной snapshot:
    `state.ai.history = [{at, blockId, score, summary}, …]` + sparkline в
    page-header.

23. **`confidence` отображается только если LLM вернул.**
    `aiRenderer.js:47` — `block.confidence ? … : ''`. Но в rule-based fallback
    это поле не выставляется, и пользователь не понимает, почему «AI Анализ»
    иногда даёт уверенность, иногда нет. Должен быть deterministic confidence
    для fallback (например, по объёму данных: <20 строк → low, 20–100 → medium,
    >100 → high).

24. **Действие «Показать задачи» применяет первый встреченный фильтр.**
    `aiView.js:222–225` — `block?.recommendations?.find(r => r.filter)?.filter
    || block?.filterPayload`. Если рекомендаций несколько, пользователь не
    знает, какую именно увидит после перехода. Должно быть либо modal-выбор,
    либо подпись на кнопке («→ задачи: <release X, blocked>»).

25. **Empty state не помогает.**
    `aiRenderer.js:337–343`: «Нет данных для анализа. Загрузите данные плана
    (CSV или XLSX)…». Но кнопок нет — ни «Импорт», ни ссылки на нужный
    раздел. Должна быть `<button>` → `App.goTo('settings.import')` или
    onboarding-tip.

## TL;DR

- Текущая иконка sidebar — гибрид робота-стетоскопа, не брендовый.
- В UI 4 разных emoji (🤖, ✨, 🔴/🟡/🔵, ⏳, ↺) при явном правиле «без
  emoji в production» из CLAUDE.md.
- Палитра 9 hex-констант обходит фирменные токены `--prizma-*`.
- HTML: `id="ai-root"` дублируется, нет `<h1>`, фильтры в data-attr без
  escape, sequential `await` блокирует UI на 1.5 минуты.
- UX: 13 блоков без кластеризации, нет временно́й кривой «прогноза курса»,
  нет autoplay-симуляции «если ничего не менять», нет истории, нет экспорта
  отчёта.
- Замена иконки: восьмилучевая звезда + sparkle (Вариант A) или звезда с
  хвостом-траекторией (Вариант B) — оба строго по `BRAND_BOOK.md § 2`.
