# QA / краевые случаи — экспертный аудит Ганта 3.0

> Эксперт: QA Lead (ручной + статический разбор кода). Дата: 2026-05-25.
> Объект: `views/gantt3.js` (6888 строк) + `onboarding/demoData.js`, в сравнении с эталоном `views/gantt.js`.
>
> **Как тестировал.** Полный статический разбор всех 11 toggle-режимов
> (lens / focus-lane / cmd / narrative / northstar / diff / burndown / chips /
> suggest / annotations / density) и 9 «Видов» (split / zen / datagrid / report /
> scrubber / deck / mission / merge / anatomy), их жизненного цикла
> (enter → render → re-render → exit/Esc/close), teardown слушателей/таймеров/
> оверлеев, пост-рендер ре-применения (`renderDetailedTasks` строки 5214–5264),
> взаимодействия с `state.activeSection`/навигацией, z-index стека и эскейп-
> цепочек. Демо-данные (`loadDemoData`) разобраны построчно. Прогнал
> `node --check` (синтаксис OK).
>
> **Важная оговорка про live-прогон.** В этом снимке (`prisma_new_design_v2`)
> корневой `app.js` — это бандл (132 КБ, одна строка), в котором **нет** ни
> одной ссылки на `gantt3` / `Gantt3View`, и dev-сервер на :5470 отдаёт `app.js`
> размером 0 байт. То есть полноценно «потыкать» вкладку в этом снимке нельзя —
> приложение не бутстрапит секцию `gantt3`. Поэтому находки ниже —
> **статические, на уровне исходника** `views/gantt3.js` (этот же файл уезжает в
> рабочую папку `prisma_new_design`, где бандл собран). Шаги воспроизведения
> даны для рабочего окружения, где секция грузится.

## Резюме

`gantt3.js` — это очень аккуратно сделанный форк: teardown слушателей,
пост-рендер ре-применение тоглов (5214–5264), cycle-safe граф зависимостей,
сплошной `Utils.escapeHtml`, empty-state на пустом плане, scoped-CSS под
`#section-gantt3`. Архитектурно — крепко.

**Но при форке не были перепортированы три guard'а `state.activeSection !== 'gantt'`**
(строки 1507, 5515, 5692). В новой секции `activeSection === 'gantt3'`, поэтому
эти условия **всегда истинны** → они «съедают» (а) drag-and-drop перенос пилюль
между колодцами — **главную фичу Ганта**, (б) клавиатурный drag-перенос,
(в) палитру ⌘K. Это самый тяжёлый дефект: ядро вкладки молча не работает,
а оригинальный Гант (`activeSection==='gantt'`) — работает, что маскирует баг
при беглой проверке.

Второй пласт — **краевые случаи, которые форк-каркас не закрыл**:
пустой план (план опустошён при активных тоглах → ре-применение пропускается,
строки-полоски остаются «висеть»); фоновый таймер «Истории/scrubber» и body-
level поповеры утекают при навигации (нет teardown на смену секции); дубликаты
эпиков в демо-данных ломают «по-эпиковые» Виды (split/zen/datagrid/deck/mission
показывают один эпик дважды); «Адаптивная» плотность не переживает перезагрузку.

Итог по severity: **P0 — 0, P1 — 3, P2 — 13, P3 — 11** (27 находок).

> Почему drag-drop помечен **P1**, а не P0: фича ломается только на новой
> вкладке `gantt3` (эталонный Гант не затронут), краша/потери данных нет —
> перенос просто молча не происходит. Но для «рабочей копии Ганта» это
> фактически выводит из строя её главную функцию, поэтому в плане правок — №1.

### P1 — критично (ядро вкладки не работает)

**G3-01 · P1 · DnD-перенос пилюль молча не работает на вкладке `gantt3`**
`views/gantt3.js:5515`
```js
if (state.activeSection && state.activeSection !== 'gantt') return;
```
- **Контекст:** это guard в `drop`-хендлере ячейки («не мутируй state, если юзер
  уже ушёл со вкладки»). Скопирован из `gantt.js:2530` без правки имени секции.
- **Факт:** секция называется `gantt3` (index.html:874 `data-section="gantt3"`,
  app/nav.js:50 `state.activeSection = section`). Значит на этой вкладке
  `state.activeSection === 'gantt3'` → условие `&& 'gantt3' !== 'gantt'` всегда
  истинно → `return` срабатывает **на каждом валидном дропе**, ДО
  `moveWtBetweenCols`.
- **Шаги:** открыть «Гант 3.0» → перетащить пилюлю в другой колодец того же
  эпика. Подсветка дропзоны, dragover-кольцо отрабатывают, но после отпускания
  — **ничего**: ни переноса, ни тоста, ни trail-стрелки. Пилюля остаётся на
  месте. (Cross-epic / same-col тосты при этом показываются — они выше guard'а,
  строки 5503/5508, что усиливает иллюзию «работает».)
- **Ожидаемо:** перенос проходит, как в оригинальном Ганте.
- **Рекомендация:** заменить на `!== 'gantt3'` (или, лучше, проверять
  `document.documentElement.dataset.activeSection !== 'gantt3'`, как уже
  сделано в строках 1914/2311/2859). Тот же фикс — для G3-02 и G3-03.

**G3-02 · P1 · Клавиатурный drag-перенос (`_executeDrop`) тоже мёртв**
`views/gantt3.js:5692`
```js
if (state.activeSection && state.activeSection !== 'gantt') return false;
```

- **Рекомендация:** `!== 'gantt3'`.

**G3-03 · P1 · Палитра ⌘K / Ctrl+K не открывается на `gantt3`**
`views/gantt3.js:1507`
```js
if (state.activeSection !== 'gantt') return;
```
- **Контекст:** глобальный keydown-guard в `bindJumpPalette` (1488): «не
  перехватывать ⌘K вне вкладки Ганта».
- **Факт:** на `gantt3` условие всегда истинно → `return` → палитра прыжков
  по командам/эпикам **никогда не открывается по хоткею**. (Кнопка
  `#btn-gantt3-jump`, строка 1499, открывает её напрямую — мимо guard'а — так
  что баг проявляется только на клавиатуре.)
- **Шаги:** на вкладке Гант 3.0 нажать ⌘K (Mac) / Ctrl+K — ничего. Кнопка
  «Поиск» при этом работает (вводит в заблуждение).
- **Рекомендация:** `!== 'gantt3'`. Заодно сверить, что `bindJumpPalette`
  навешивает один глобальный listener (флаг `_jumpBound`, 1489 — OK), иначе
  при наличии и `gantt`, и `gantt3` оба слушателя живут параллельно.

**G3-04 · P2 · Пустой план при активных тоглах: ре-применение пропускается**
`views/gantt3.js:4084` (ранний `return`) vs блок ре-применения `5214–5264`
- **Контекст:** весь пост-рендер блок, который пере-вешивает тоглы (chips,
  burndown, diff, northstar, annot, lens-decor, cmd-фильтр) и закрывает
  поповеры (`_peekClose`, `_radialClose`, `_anatomyClose`, `_marqueeHideBar`),
  находится **внутри** `renderDetailedTasks`. А при пустом плане
  `_renderChartImmediate` выходит раньше:
  ```js
  if (!rows.length){ wrap.innerHTML = '<div class="empty-state">…'; return; }
  ```
- **Факт:** если включить, например, «Чипы» / «Курс» / «Командный режим», а
  затем опустошить план (удалить все строки, или применить фильтр в 0
  результатов), то: grid сменится на empty-state, но строки-полоски
  `#gdt-chips` / `#gdt-northstar` / `#gdt-cmd-bar` (они sibling'и `wrap`,
  insert через `wrap.parentNode`) **остаются висеть** над пустым местом со
  стухшими счётчиками; кнопки тоглов остаются `active`; открытые
  поповеры/marquee-бар не закрываются.
- **Шаги:** демо-данные → «Чипы» → снять все эпики (или фильтр без совпадений)
  → строка чипов остаётся с числами от старого плана.
- **Ожидаемо:** на пустом плане тогл-хром убирается или показывает «нет данных».
- **Рекомендация:** вынести closing-часть (закрыть поповеры, спрятать
  marquee/chips/northstar/cmd-bar) из тела `renderDetailedTasks` в общий хвост
  `_renderChartImmediate`, который выполняется и на empty-пути.

**G3-05 · P2 · Дубликаты эпиков ломают «по-эпиковые» Виды (split/zen/datagrid/deck/mission)**
`views/gantt3.js:3146` (`_collectEpics`), `onboarding/demoData.js:74–293`
- **Контекст:** `_collectEpics` строит список эпиков из **каждой**
  `.gantt-row[data-epic-key]`. А grid рендерит **одну строку на каждую запись
  `state.rows`** (4530), причём `_epicKey = row.epic` (4564). В демо-данных
  **7 эпиков заведены дважды** (две строки на эпик в одной команде): «Новый
  процессинг платежей SBP», «Дашборд KYC-метрик», «Рефакторинг расчёта
  лимитов», «Интеграция с НСПК», «Автоматическое одобрение кредитов», «Редизайн
  главного экрана», «СМЭВ3 адаптер».
- **Факт:** Сплит-список, Дзен-пейджер, Таблица, Дек, Центр управления
  показывают эти эпики **дважды** как отдельные карточки/строки с одинаковым
  именем и «располовиненными» данными (у каждой строки только свои пилюли).
  Дзен заявляет «один эпик крупно», но листает дубли. В Таблице итог
  «N эпиков» завышен. (В живом гриде это терпимо — каждая строка это
  team-epic-срез, но новые модули позиционируются как per-epic.)
- **Шаги:** демо → «Виды ▾» → «Дзен-фокус» → стрелки: «Дашборд KYC-метрик»
  встречается два раза подряд.
- **Ожидаемо:** агрегация по имени эпика (merge строк) в `_collectEpics`.
- **Рекомендация:** в `_collectEpics` группировать `out.epics` по
  `epic`-имени, сливая cells/total/done/who. Это же чинит G3-06.

```js
if (k && !els[k]) els[k] = el;   // только первое вхождение
```

**G3-07 · P2 · Фоновый таймер «Истории/scrubber» утекает при навигации**
`views/gantt3.js:3491–3496` (play `setInterval`), нет teardown на смену секции
- **Контекст:** `_mode_scrubber` ставит `setInterval` (каждые 750 мс) на
  «Проиграть». `_modeClose` корректно его чистит (3244). НО **смены секции не
  вызывают `_modeClose`** — оверлей `#gdt-mode` лишь скрывается CSS-правилом
  (798), а объект `Gantt3View._mode` и его таймер живут.
- **Факт:** открыть «Виды ▾ → История», нажать «Проиграть», уйти на другую
  вкладку, не закрыв вид. Оверлей скрылся, но `setInterval` продолжает крутиться
  — каждые 750 мс инкрементит скрытый range и зовёт `render()` для скрытого
  stage, пока не дойдёт до N. Пустая работа + неожиданный фоновый таймер.
- **Шаги:** демо → История → Проиграть → переключиться на «Реестр» → таймер
  жив (виден в profiler / по `Gantt3View._mode.st.timer`).
- **Рекомендация:** добавить teardown гант-режимов/тоглов по
  `data-active-section` change (хук в nav или `visibilitychange`/`MutationObserver`),
  как минимум `_modeClose()` + остановку таймеров при уходе с `gantt3`.

**G3-09 · P2 · «Адаптивная» плотность не переживает перезагрузку**
`views/gantt3.js:1482` (`_densityApplyAuto` пишет `'auto'`) vs `1417` (`applyDensity` не знает `'auto'`)
```js
// _densityApplyAuto: localStorage.setItem('q2_gantt3_density_v16', 'auto')
// applyDensity:  if (saved==='compact'||'regular'||'minimal'||'overview') mode = saved;
```
- **Факт:** при выборе «Адаптивная» в localStorage пишется `'auto'`. Но
  `applyDensity` (вызывается в `render()`, 1195) этого значения не признаёт →
  откатывает на `'regular'`, а флаг `_densityAuto` остаётся `false`. После
  перезагрузки/повторного входа в секцию выбор «Адаптивная» молча теряется.
- **Шаги:** Плотность → кликать до «Адаптивная» → F5 → плотность снова Regular.
- **Рекомендация:** в `applyDensity` обработать `saved==='auto'`: выставить
  `_densityAuto=true` и вызвать `_densityApplyAuto()` после первого
  `renderChart` (либо отложенно, т.к. число строк ещё не известно).

**G3-10 · P2 · Фокус-дорожка показывает СТУХШИЕ данные после мутации грида**
`views/gantt3.js:2193` (`FL._data` снимок), `5227–5229` (ре-рендер только `_focusLaneBind`)
- **Контекст:** `_focusLaneEnter` снимает `FL._data = _collectEpics()` один раз.
  Пост-рендер блок при активной фокус-дорожке вызывает только `_focusLaneBind()`

- **Факт:** открыть Фокус-дорожку, затем переименовать эпик (inline-edit) или
  перетащить пилюлю (в рабочем окружении, после фикса G3-01) → оверлей

  планом.
- **Рекомендация:** при активной фокус-дорожке в пост-рендере пересобирать
  `FL._data = _collectEpics()` и звать `_focusLaneRender()`.

**G3-11 · P2 · Нарратив — статичный снимок, не реагирует на изменения плана**

**G3-12 · P2 · Один Esc закрывает СРАЗУ несколько режимов**
`views/gantt3.js` — глобальные capture-keydown: lens(1912), focus-lane(2208),
narrative(2745), mode(3232), marquee(2858)
- **Контекст:** взаимного исключения режимов нет (каждый тогл независим). Все
  вешают свой `document.addEventListener('keydown', …, true)`.
- **Факт:** если одновременно открыты, например, Линза + Нарратив (Линза —
  тогл, Нарратив — оверлей), один Esc вызовет обработчик линзы (выход из линзы)
  И обработчик нарратива (закрытие) — закроются оба за одно нажатие. Аналогично
  Линза + любой «Вид» (mode.onKey): Esc закроет Вид и одновременно выйдет из
  Линзы. Неожиданно для пользователя (ждёт «отмена верхнего слоя»).
- **Рекомендация:** ввести Esc-стек/приоритет (закрывать только самый верхний
  слой; `stopImmediatePropagation` в обработчике верхнего оверлея), либо
  у оверлеев (`mode`/`narrative`/`focus`) гасить событие.

**G3-13 · P2 · Shift+тяни, НАЧАТАЯ на пилюле, конфликтует с нативным drag**
`views/gantt3.js:2853–2857` (marquee pointerdown) vs `5455` (dragstart без shift-guard)
- **Контекст:** marquee стартует на `pointerdown` при Shift и делает
  `e.preventDefault()` с комментарием «отменяет native pill-drag». Но
  `preventDefault()` на `pointerdown` **не гарантированно** подавляет нативный
  `dragstart` у `draggable`-элемента (поведение зависит от браузера). А в
  `dragstart`-хендлере пилюли (5455) **нет** проверки `e.shiftKey`.
- **Факт:** Shift+зажать на пилюле и тянуть — возможны: (а) запускается нативный
  pill-drag вместо/вместе с marquee, (б) «фантомная» drag-картинка пилюли поверх
  рамки. На пустом месте ячейки marquee работает чисто; на пилюле — ambiguous.
- **Рекомендация:** в `dragstart`-хендлере: `if (e.shiftKey) { e.preventDefault(); return; }`.
