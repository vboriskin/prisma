# Design audit — итог

> Папка `design-audit/` — полный отчёт от команды экспертов по визуальному и UX-аудиту СБОФ Планировщика. **Никакого кода не менялось** — только исследование и предложения.

---

## TL;DR

**Текущий продукт** — функциональный, аккуратный, технически грамотный B2B-инструмент. Закрывает workflow на 9 из 10 в плане «нашёл, поменял, сохранил». Но визуально — **«никакой»**: indigo-default акцент, system Inter, 15+ карточек одного веса на дашборде, эмодзи вместо иконок, motion осторожный без сильных моментов. Это инструмент, который **не запоминается**.

**Главные UX-проблемы**:
1. Дашборд показывает **состояние**, а не **что требует действия сейчас**.
2. 6 разных табов для одних и тех же задач (Реестр / Гант / Канбан / Timeline / Подложка / Сводка).
3. Нет визуальной hero/body/reference-иерархии — всё одного веса.
4. Активный таб слабо отличается от неактивного.

**Главные визуальные проблемы**:
1. Indigo-акцент — default-tier выбор, не дифференцирует.
2. Все шрифты Inter без display-pair — нет «больших моментов».
3. Эмодзи как icon-system — отсутствует пластика.
4. Нет иллюстраций / hero-блоков / точечных decorative-элементов.

**Главные a11y-проблемы**:
1. `--text-4` `#9ca3af` (3.4:1) — fail для small text.
2. Нет `prefers-reduced-motion` поддержки.
3. Focus-visible непоследователен (nav-items пропадают).
4. Hit-targets ниже WCAG AA (44×44).

**Что точно нельзя ломать**: 4-уровневая текст-иерархия, status-цвета (emerald/amber/red), tabular-nums в number-cells, темная тема, compact 36px row в Реестре, drag-and-drop в Ганте.

## Моя рекомендация

> Это **не выбор «правильного» направления**, это выбор **позиционирования**. Я могу предложить только то, что считаю **наиболее жизнеспособным** в контексте.

### Рекомендую: **B. Editorial Bold** + элементы **A**

**Почему B как основа**:

1. **Долгосрочная ценность**: A — modernise quietly, через год выглядит как все остальные. B — создаёт **identity**, которая работает 3-5 лет.

2. **Pres-ready**: дашборд можно положить в quarterly review для CTO/CEO. A для этого слишком тих, C — слишком бунтарский.

3. **Привлекает таланты**: новые сотрудники Сбера видят «Q2 Planner» и думают «у нас современные внутренние тулзы». Это влияет на retention.

4. **Совместимо с корпоративной культурой Сбера** — есть прецеденты bold-design (СберПервый, СберBank Online имеют characterful UI). Editorial Bold не выходит за рамки приемлемого.

5. **Pleasure of use**: пользователи, которые работают по 8 часов в день, **выгорают** от neutral environment. Editorial — это micro-pleasure от интерфейса, который нравится.

**Почему «+ элементы A»** (не чистый B):

- B как описано — agressive: vermilion + forest + 72px headlines + serif accents. Для **первого редизайна** этого внутреннего тула — слишком резкий jump.
- Гибрид: **B-палитра + B-типографика + A-density** (плотный density Реестра/Ганта оставить, B-стили применить только к Дашборду + welcome-states).
- То есть: **«Editorial dashboard, calm work surfaces»**.

### Альтернативная рекомендация: **A — если приоритет = низкий риск + быстрый ship**

Если команда хочет быстро shipnut UPD без opinionated-disagreements — A. Это **гарантированно не сломает** ничего, заметно улучшит UX, и через 3-4 недели — production. Но через год вы захотите снова что-то делать, потому что character не появится.

### Когда выбирать C: **если product hands команда инженеров с opinionated-вкусом**

Это смелый выбор для случая, когда команда **подписывается** под opinionated-design. Если есть один stakeholder, который скажет «это слишком экзотично» — C развалится. C нужен полный consensus.

## Общие предупреждения для любой концепции

### 1. Это не «переписать все стили»

Любой редизайн начинается с **token-миграции** (отчёт `07-design-system.md`). Сначала переводим текущий `styles.css` на двухуровневую систему (primitives + semantic). Это 1-2 недели работы **без визуальных изменений**. Только после — применяем concept-specific values.

### 2. Не трогать рабочий density Реестра / Ганта

Все три концепции **сохраняют 36px row-height в Реестре** и **компактные pills в Ганте**. Это — рабочая поверхность опытного пользователя, и любое разбухание сломает workflow.

Концепции применяются прежде всего к **«вход-точкам»**: Дашборд, welcome, empty-states, modals (Tech Info, settings), LLM panel. Реестр и Гант — обновляются меньше, в основном через типографику, цвет, focus-states.

### 3. A11y — must, не nice-to-have

Любая концепция должна **проходить WCAG 2.1 AA**: контраст 4.5:1 для всех body, focus-visible на всех interactive, `prefers-reduced-motion` поддержка, ARIA на модалках. Это **non-negotiable** в корпоративной среде.

### 4. Новые шрифты vs current

Любая концепция **выигрывает от webfont** (vendored woff2 в `libs/`). Если **нельзя** — типографически достижим только B + Inter pair с variable axes. C критически зависит от mono — без webfont не сработает.

## Roadmap (если выбрана концепция B)

**Phase 0 — Подготовка** (1-2 недели)
- Token-миграция (см. `07-design-system.md`).
- Тестовое vendoring webfont (Inter Variable + Plus Jakarta + JetBrains Mono).
- Setup `prefers-reduced-motion` global.

**Phase 1 — Foundations** (2-3 недели)
- Применить новую палитру (vermilion + forest + cream).
- Type-scale: 32/48/56/72px headlines внедрены.
- Lucide-иконки заменяют эмодзи.
- Welcome screen + onboarding получают illustrations (5-7 SVG).

**Phase 2 — Dashboard redesign** (1-2 недели)
- Hero-block «Critical attention» на forest background.
- Bento-grid layout для releases / risks / teams.
- Stagger reveal motion + KPI countup.

**Phase 3 — Surfaces redesign** (1-2 недели)
- Tech Info / Black Dashboard / LLM panel — editorial typography + new colours.
- Modal motion (slide-transition в LLM, hero-banner в Tech Info).

**Phase 4 — Power-surfaces полировка** (1-2 недели)
- Реестр / Гант / Канбан — точечные обновления (focus-states, hover, drag-drop motion).
- Не разбухаем density.
- A11y full sweep.

**Phase 5 — Validation** (1 неделя)
- User-testing с 5-10 фактическими пользователями.
- A11y testing (axe, keyboard-only, NVDA).
- Performance testing (новые шрифты, motion budget).
- Iterate.

**Total: 7-12 недель** (плюс-минус, зависит от размера команды).

## Вопросы ко мне (вам как заказчику) — нужно решить перед началом

> Я сознательно **не отвечал на эти вопросы за вас** в отчётах — это не дизайнерские, это бизнес-/продуктовые/политические решения. После ваших ответов смогу finalise концепцию и идти в Phase 0.

### Стратегия и позиционирование

1. **Какое из трёх направлений резонирует** с вашим видением? (A / B / C / гибрид)
2. **Готов ли продукт «иметь характер»**, или нужно остаться в нейтральной B2B-эстетике?
3. **Кто стейкхолдеры**, которые должны одобрить bold-decisions (vermilion accent, forest hero, mono-везде)? Если такого человека одного нет — может быть проще выбрать A.
4. Этот **продукт growth** (привлекает новых пользователей, нужен «вау») или **maintenance** (закрывает текущий workflow и должен просто работать)? B нужен для первого, A — для второго.

### Технические ограничения

5. **Можно ли вендорить webfont** (1-1.5 MB woff2 в `libs/`)? Это разрешит и B, и C.
6. **Кто отвечает за иллюстрации** (5-7 custom SVG для B)? Внутренний дизайнер? Подряд? Пока не делаем?
7. **Бюджет времени** — сколько недель команда готова инвестировать? Это влияет на phase-outs.

### Аудитория и сценарии

8. **На каком устройстве работают пользователи** — laptop 14"-15", desktop 24"+? Это влияет на bento-layouts и hero-blocks (на 14" hero-banner 320px высоты — это много).
9. **Часто ли заходят люди извне команды** (топы, аудиторы, новички)? Если да — UX hero-block «что требует внимания» оправдан больше, чем для daily-users.
10. **Как часто пользователь делает скриншот для отправки коллеге** (в Slack, на review)? Если часто — pres-ready visuals критичны (B).

### Brand и identity

11. **Связь с identity Сбера** — должен ли инструмент **визуально дополнять** SberBank-стиль (зелёный, СберSans, geometric) или быть **отдельным** под-брендом?
12. **Имя продукта** — оставляем «СБОФ Планировщик»? Или редизайн — повод для rename? («СБОФ» — глухое аббревиатура, «Планировщик» — generic. Возможно стоит подумать про имя типа «Q2 Planner», «Pulse», «Cadence» — что-то более product-named.)
13. **Свобода в creative** — могу ли я при детальной разработке отклоняться от концепции в небольших моментах (типа character-illustrations), или каждое решение проходит через one-by-one approval?
